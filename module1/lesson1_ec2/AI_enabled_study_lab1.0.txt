['Ultimate AWS certified. Solutions Architect Associate 2026'](https://www.udemy.com/course/aws-certified-solutions-architect-associate-saa-c03)

Section 21, “Databases in AWS,” surveys the major managed database services on AWS and the criteria for choosing among them. It starts with how to pick the right database based on factors like read/write patterns, consistency needs, and relational vs. non-relational data, then covers RDS (managed relational databases for MySQL, PostgreSQL, MariaDB, Oracle, and SQL Server) and Aurora (AWS’s high-performance, MySQL/PostgreSQL-compatible relational database with better scalability and availability than standard RDS). It moves into ElastiCache (managed Redis/Memcached for in-memory caching to reduce database load and improve latency) and DynamoDB (a fully managed, serverless NoSQL key-value and document database built for massive scale with single-digit millisecond performance). It also touches on using S3 itself as a data store, then introduces several more specialized managed databases: DocumentDB (MongoDB-compatible document database), Neptune (a graph database for highly connected data), Keyspaces (a managed service compatible with Apache Cassandra), and Timestream (a purpose-built time-series database). For exam purposes, the key is matching each service to its ideal use case — relational transactional workloads, caching, key-value/NoSQL at scale, document storage, graph relationships, wide-column data, or time-series data — rather than memorizing deep implementation details

[`AWS security, identity, and compliance services 2019`](https://mega.nz/folder/N80jAbqB#aWmzei2E6cbGK0513O6NBQ/folder/B8sGhIBY)

AWS’s security, identity, and compliance services cover identity management, threat detection, data protection, and compliance auditing across the cloud environment. IAM sits at the core, letting you create users, groups, and roles with fine-grained permissions to control access to AWS resources, while Single Sign-On extends this by letting organizations use their existing corporate authentication to access multiple AWS applications from one place. For protecting workloads and data, Inspector runs automated security assessments on EC2 instances, GuardDuty continuously monitors the account for threats using intelligent detection, and Macie uses machine learning to discover and classify sensitive data. Network and application-layer defense comes from WAF, which lets you configure rules to allow, block, or monitor web requests, and Shield, a managed service that protects against DDoS attacks. Certificate Manager handles SSL/TLS certificate creation and deployment, CloudHSM provides dedicated hardware security modules for an extra layer of protection meeting strict regulatory requirements, and Secrets Manager centralizes the management, retrieval, and rotation of credentials and API keys. Rounding out the group, Directory Service enables Microsoft Active Directory–aware workloads in AWS, Cognito provides sign-up and authentication tools (with data sync) for web and mobile apps, and Artifact offers on-demand access to compliance documents like ISO, PCI DSS, SOC, and HIPAA reports needed by auditors and regulators.

Self-hosted environments for Claude Code, announced August 6, 2026 and now in public beta, let organizations run Claude Code sessions on their own infrastructure instead of Anthropic’s hosted servers, so sessions execute inside the company’s network alongside internal services, toolchains, and security controls. Teams adopt this mainly for three reasons: it gives sessions access to internal databases and registries without exposing them to the public internet, it lets organizations pre-install their own compilers, SDKs, and internal CLIs so every session starts ready to build, and it keeps source code and build artifacts on infrastructure they control for compliance purposes. Technically, organizations deploy long-lived “runner” processes that pick up sessions and launch a Claude Code process for each one, operating in either a fixed mode (a set number of runners always running) or an on-demand mode (an orchestrator spins runners up and down as sessions arrive and finish); each session gets its own isolated checkout even though a runner can serve multiple sessions, and sessions from any supported surface (web, mobile, desktop, or a routine) route to the same environment. It’s important to note that even in self-hosted mode, the conversation itself — prompts, responses, and tool results — is still sent to Anthropic for inference and transcript storage, only the repo checkouts, build artifacts, and secrets stay fully on the customer’s own infrastructure. This feature is distinct from “Remote Control” (which lets a developer continue a session running on their own machine from phone or browser, tied to that individual user and ending when their machine stops), and is available in public beta only to Claude Team and Enterprise plans that are not using ZDR, with the expectation that a platform or developer-productivity team will own ongoing setup and maintenance.
