3.4 Starting the API
Model ID and region are read from environment variables when the server starts. Putting model_id and region in
the curl JSON body does nothing (you tried it). The working form:

    BEDROCK_MODEL_ID=us.anthropic.claude-sonnet-4-6 AWS_REGION=us-east-1 \
      uvicorn app.main:app --host 0.0.0.0 --port 8000

You test it from a second terminal with curl -X POST http://127.0.0.1:8000/ask. The response's source field
tells you where an answer came from: "offline-knowledge-base" means the app did not call Bedrock.

3.5 Why /ask stayed offline
- Symptom: every response said offline-knowledge-base, even with the variables set.
- The app's rule: Bedrock answers only if an IAM role is attached to the instance, AWS_REGION is right, and
  BEDROCK_MODEL_ID is a real inference-profile ID.
- Finding: aws ec2 describe-instances showed the instance had no IAM instance profile, so no credentials,
  so a silent fall-back to offline. Claude could not test from inside the instance (no SSM agent, no SSH from its
  side), so the diagnosis came from AWS-side checks.
- Fix (by Claude, with your approval): six steps, listed in the AWS changes table below.
- Verification (by you, on the instance): aws sts get-caller-identity showed the assumed role, and the
  Converse call returned pong in about 690 ms. One early attempt failed from a copy/paste slip (a stray quote and a
  second command pasted into it); it was cancelled and was not an AWS error.
- Honest caveat in the file: it says the missing profile was the real cause, but "I don't know whether the earlier
  restarts had the variables set, so I can't say how much they contributed."
- Rollback listed: disassociate-iam-instance-profile, remove-role-from-instance-profile,
  delete-instance-profile, delete-role-policy, delete-role.

3.7 COBOL return codes 8 and 12
You asked Claude to read the instructor's repo (BalericaAI/SEIR-Foundations). Claude cloned it to a throw-away
folder under /tmp and only read it; it ran none of its code.

  Code  |  Meaning
  0  |  Success
  4  |  Warning (account not found)
  8  |  Business rejection (account not ACTIVE, zero amount, insufficient funds)
  12  |  Environment failure (missing or unwritable file, malformed arguments)

- Code 8: run from /opt/balerica-bank, payment_post ... 0 ... (zero amount) or a huge amount (insufficient
  funds), or account_lookup with no argument. A non-ACTIVE account also gives 8, but only if you hand-edit
  data/accounts.dat (status is columns 37 to 44).
- Code 12, first idea failed through the API: running a COBOL program from the wrong folder gives 12 with
  FILE-STATUS=35 on the command line, but the web app runs it with cwd=BANK_HOME and rewrites accounts.dat
  before every call, so that route cannot be triggered from the UI.
- Code 12, what worked: chmod 444 /opt/balerica-bank/data/payments.dat, then a POST /payments at /docs
  returns HTTP 422 with cobol_return_code: 12 ("CANNOT OPEN data/payments.dat"). Then chmod 644 to restore it,
  or every later payment fails. The failed attempts also show up as REJECTED rows.
- An untested idea: sending a six-space account_id and three-space currency was derived from the code, never
  tested, and would save a row with a blank account ID, so you did not use it.

3.8 Reading the fixed-width ledger
data/accounts.dat has no delimiters; each record is 59 characters.

  Field  |  Columns  |  Width
  Account ID  |  1 to 6  |  6
  Customer name  |  7 to 36  |  30
  Status  |  37 to 44  |  8
  Balance  |  45 to 56  |  12 digits, implied decimal
  Currency  |  57 to 59  |  3

You read it with cut -c1-6, cut -c7-36, cut -c45-56, and grep '^100001' ... | cut -c45-56 | awk '{printf
"%.2f\n", $1/100}'. The COBOL picture PIC 9(10)V99 means 10 digits, an implied decimal point, then 2 digits, so
000000475652 decodes to 4756.52. Two mistakes the file flags for reviewers: printf("Account ID" + cut ...) is
C/Python syntax and does not work in a shell, and grep 'TXN-XX-' data/payments.dat finds nothing because real IDs
are TXN plus 17 digits with no dashes (TXN-XX- is a placeholder in the lab text).
